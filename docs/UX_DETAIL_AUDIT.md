# Mirror 项目 UX 细节审查报告

**日期**: 2026-05-13  
**审查范围**: 核心用户流程（首页 → 上传 → 进度 → 结果）  
**设计语言**: Kenya Hara 极简主义（奶油色、棕色、衬线体、直角）

---

## 核心场景定义

**主流程**: 用户上传长文本 → 等待蒸馏完成 → 查看结果并导出

**关键成功指标**:
1. 用户能顺利完成上传（表单验证清晰、错误提示有用）
2. 用户能理解进度状态（知道当前在做什么、还要等多久）
3. 用户能快速找到结果（导出按钮明显、格式选择清晰）

---

## 场景 1: 首页 → 创建任务

### 当前体验走查

**用户进入首页后看到**:
- Hero 区域：标题 + 副标题 + "创建任务"按钮
- 任务列表：显示所有历史任务，带筛选器

**问题诊断**:

#### P1 - 主按钮位置不顺手
- **现象**: "创建任务"按钮在 Hero 区域顶部，但用户刚看完任务列表后想创建新任务，需要滚回顶部
- **影响**: 增加操作步骤，打断用户心流
- **修复**: 在任务列表底部也添加一个"创建新任务"按钮（次要样式）

#### P1 - 筛选器位置不明显
- **现象**: 筛选器在任务列表上方，但视觉层级不够（和标题平级）
- **影响**: 用户可能忽略筛选功能，在长列表里手动找任务
- **修复**: 增强筛选器视觉层级（加背景色或边框），或改为下拉菜单样式

#### P2 - 任务卡片信息密度过高
- **现象**: 每个任务卡片显示：标题、状态标签、任务ID、创建时间、更新时间、进度条、2个按钮
- **影响**: 视觉拥挤，用户需要花时间解析信息
- **修复**: 
  - 任务 ID 移到 hover tooltip 或详情页
  - 创建时间和更新时间合并为"最后更新"
  - 进度条只在进行中的任务显示

#### ~~P2 - 按钮点击区域偏小~~
- ~~移动端适配，不做~~

#### P3 - 空状态缺少引导
- **现象**: 空状态只显示"还没有任务，开始创建第一个蒸馏任务吧"
- **影响**: 新用户不知道蒸馏是什么、能做什么
- **修复**: 添加简短的功能说明（例如："将长文本提炼为结构化知识图谱"）

## 场景 2: 上传页面

### 当前体验走查

**用户操作流程**:
1. 输入任务标题
2. 粘贴文本或上传文件
3. 看到字数统计和验证提示
4. 点击"开始蒸馏"

**问题诊断**:

#### P0 - 文件上传无反馈
- **现象**: 点击"上传文件"后，如果文件较大，没有加载提示
- **影响**: 用户不知道是否上传成功，可能重复点击
- **修复**: 添加文件读取中的 loading 状态（"读取文件中..."）

#### P1 - 字数统计位置不顺手
- **现象**: 字数统计在文本框右下角，用户输入时需要移动视线
- **影响**: 用户不能实时感知是否达到要求
- **修复**: 字数统计移到文本框上方（和"文本内容"标签同行），实时更新

#### P1 - 错误提示时机不合理
- **现象**: 只有点击"开始蒸馏"后才显示错误（例如"文本内容至少需要 1000 字"）
- **影响**: 用户填完表单才发现不符合要求，体验受挫
- **修复**: 实时显示验证状态（字数不足时显示"还需要 X 字"，而不是等提交时才报错）

#### P1 - 提交按钮 disabled 状态不清晰
- **现象**: 按钮 disabled 时只是变灰，没有说明为什么不能点击
- **影响**: 用户不知道如何解决问题
- **修复**: disabled 时在按钮下方显示原因（例如"字数不足，还需要 500 字"）

#### P2 - 文本框高度固定
- **现象**: 文本框最小高度 300px，对于长文本（10000+ 字）需要大量滚动
- **影响**: 用户难以浏览和编辑长文本
- **修复**: 文本框支持自动扩展（或提供"全屏编辑"模式）

#### P2 - 缺少粘贴反馈
- **现象**: 用户粘贴大段文本后，没有视觉反馈（例如字数跳变动画）
- **影响**: 用户不确定是否粘贴成功
- **修复**: 粘贴后字数统计短暂高亮（0.5s 绿色闪烁）

#### P3 - 文件类型限制不明确
- **现象**: 只接受 .txt 和 .md 文件，但用户可能尝试上传 .docx 或 .pdf
- **影响**: 上传失败后没有明确提示
- **修复**: 添加文件类型验证，拒绝时显示"仅支持 .txt 和 .md 文件"

## 场景 3: 进度页面

### 当前体验走查

**用户操作流程**:
1. 提交任务后自动跳转到进度页
2. 看到整体进度条和各层状态
3. 等待任务完成（页面每 3 秒自动刷新）
4. 完成后点击"查看结果"

**问题诊断**:

#### P0 - 轮询无超时处理
- **现象**: 如果任务卡住（例如后端崩溃），页面会无限轮询
- **影响**: 用户不知道任务是否真的在运行，浪费时间等待
- **修复**: 添加轮询超时（例如 10 分钟），超时后显示"任务可能遇到问题，请刷新页面或联系管理员"

#### P1 - 进度预估不准确
- **现象**: 进度条显示百分比，但实际时间不可预测（Layer 1 可能 1 分钟，Layer 3 可能 5 分钟）
- **影响**: 用户对等待时间没有合理预期
- **修复**: 
  - 改为"步骤进度"而非"时间进度"（例如"第 2/4 步"）
  - 或添加预估时间（"预计还需 3-5 分钟"）

#### P1 - 错误信息不够具体
- **现象**: 失败时只显示 `error_message`，可能是技术性错误（例如"API rate limit exceeded"）
- **影响**: 用户不知道如何解决问题
- **修复**: 
  - 后端返回用户友好的错误信息（例如"API 调用次数超限，请稍后重试"）
  - 前端添加常见错误的解决方案（例如"如果问题持续，请联系管理员"）

#### P2 - 各层状态图标不一致
- **现象**: 压缩阶段用 📝 emoji，Layer 1-3 用数字
- **影响**: 视觉风格不统一
- **修复**: 统一使用数字或图标（建议用数字，更简洁）

#### P2 - "实时更新中"提示不明显
- **现象**: 绿点动画很小，用户可能忽略
- **影响**: 用户不确定页面是否在自动刷新
- **修复**: 增大绿点尺寸（4px → 6px），或改为文字提示"每 3 秒自动刷新"

#### P3 - 缺少"停止任务"功能
- **现象**: 用户无法主动停止正在运行的任务
- **影响**: 如果用户发现输入错误，只能等任务完成后删除
- **修复**: 添加"停止任务"按钮（仅在运行中显示）

## 场景 4: 结果页面

### 当前体验走查

**用户操作流程**:
1. 任务完成后点击"查看结果"
2. 看到三层蒸馏结果（可切换 Tab）
3. 点击"导出"按钮下载结果

**问题诊断**:

#### P1 - Tab 切换无键盘支持
- **现象**: 只能用鼠标点击 Tab，无法用键盘切换
- **影响**: 键盘用户（或习惯键盘导航的用户）体验差
- **修复**: 添加键盘支持（左右箭头切换 Tab，Enter 激活）

#### P1 - 导出按钮位置不固定
- **现象**: 导出按钮在页面底部，长结果需要滚动到底部才能导出
- **影响**: 用户可能找不到导出按钮
- **修复**: 
  - 导出按钮固定在右上角（sticky）
  - 或在顶部和底部都放置导出按钮

#### P2 - 导出格式选择不直观
- **现象**: 导出按钮点击后直接下载，没有格式选择界面
- **影响**: 用户不知道有多种格式可选
- **修复**: 
  - 改为下拉菜单（"导出为 JSON / Markdown / TXT"）
  - 或改为三个独立按钮（"导出 JSON"、"导出 Markdown"、"导出 TXT"）

#### P2 - 长文本无截断
- **现象**: Layer 1 结果可能有几百个段落，全部展开会导致页面很长
- **影响**: 页面滚动体验差，加载慢
- **修复**: 
  - 默认只显示前 20 个段落，点击"查看更多"展开
  - 或添加虚拟滚动（只渲染可见区域）

#### P2 - 质量报告缺少目录
- **现象**: 质量报告是长篇 Markdown，没有目录导航
- **影响**: 用户难以快速定位到感兴趣的章节
- **修复**: 添加侧边栏目录（点击跳转到对应章节）

#### P3 - 缺少分享功能
- **现象**: 用户无法分享结果链接给他人
- **影响**: 协作场景受限
- **修复**: 添加"复制分享链接"按钮（生成公开访问链接）

## 通用问题

### 交互反馈

#### P1 - 按钮 loading 状态不一致
- **现象**: 有些按钮 loading 时显示"加载中..."，有些显示 spinner
- **影响**: 视觉风格不统一
- **修复**: 统一为"文字 + spinner"（例如"加载中... ⏳"）

#### P2 - Toast 提示停留时间过短
- **现象**: 成功/错误提示 3 秒后自动消失，用户可能来不及阅读
- **影响**: 用户错过重要信息
- **修复**: 
  - 成功提示 3 秒（保持不变）
  - 错误提示 5 秒（给用户更多时间阅读）
  - 或添加"关闭"按钮，让用户主动关闭

#### P2 - 缺少操作确认
- **现象**: 删除任务时有确认弹窗，但停止任务（如果实现）没有
- **影响**: 用户可能误操作
- **修复**: 所有破坏性操作都添加确认弹窗

### 边界情况

#### P1 - 网络慢时无提示
- **现象**: API 请求慢时，页面没有 loading 提示
- **影响**: 用户以为页面卡住了
- **修复**: 所有 API 请求添加 loading 状态（超过 500ms 显示 spinner）

#### P2 - 长任务名截断不优雅
- **现象**: 任务名超过 100 字时被截断，但没有 tooltip 显示完整名称
- **影响**: 用户看不到完整任务名
- **修复**: 添加 title 属性或 tooltip，hover 时显示完整名称

#### P3 - 浏览器后退行为不明确
- **现象**: 用户在结果页点击浏览器后退，会回到进度页（但任务已完成）
- **影响**: 用户可能困惑"为什么又回到进度页"
- **修复**: 进度页检测任务已完成时，自动跳转到结果页（避免用户停留在过时页面）

## 设计原则（遵守 AGENTS.md）

1. **最小化修改** - 只改必须改的，不重构无关代码
2. **匹配现有风格** - 保持 Kenya Hara 设计语言
3. **外科手术式修改** - 每个改动都能追溯到具体问题
4. **分阶段交付** - 每个阶段独立验证和提交
