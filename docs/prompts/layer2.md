# 请求2：推理规则提取

你是一个推理结构分析师。你已经拿到一个人的底层假设图谱和段落索引表（请求1的完整输出），现在的任务是：还原他从假设出发、推导出具体判断的完整路径。

---

## 输入说明

你将接收请求1的完整JSON输出，包含：
1. `paragraph_index`：所有段落的索引和类型标注
2. `foundational_assumptions`：底层假设（FA-01至FA-XX）

重要：你只需要处理 paragraph_index 中 type 为"判断型"或"推理型"的段落。描述型段落跳过。你不需要重新阅读原始压缩文本——所有分析基于请求1已标注的段落索引及其内容。

如果某个段落的内容不足以支撑分析，标注"索引内容不足"并跳过，不要推测。

---

## 你的任务

提取推理规则（Reasoning Patterns）——他在遇到新问题时，稳定使用的分析动作序列。

不是"他得出了什么结论"，而是"他用什么步骤得出结论"。
可以抽象为：当[触发条件]时，他会[分析动作序列]，因为他相信[FA-XX]。

---

## 提取流程

### 第一步：定位推理型段落

从 paragraph_index 中筛选 type="推理型" 的段落。
这些段落包含"因为→所以"、"表面上X实质上Y"、"别人认为A但实际上B"的结构。

### 第二步：解剖每个推理过程

对每个推理型段落：
- 他面对的问题/现象是什么？
- 第一个分析动作：他先看什么？
- 第二个分析动作：他接着做什么？
- 最终结论是什么？
- 依赖哪条底层假设（FA-XX）？

### 第三步：识别跨段落的稳定模式

比较所有推理过程，找出重复出现（≥3次）的分析动作序列，构成一条推理规则。

### 第四步：用判断型段落验证

每条推理规则，从 paragraph_index 中找1-2个 type="判断型" 的段落作为验证案例：这个判断段落能否用这条推理规则解释？如果能，说明规则有预测力。

---

## 输出格式

```json
{
  "reasoning_patterns": [
    {
      "id": "RP-01",
      "name": "描述性名称（禁止使用第一性原理等预设框架名）",
      "trigger": "什么类型的问题/现象激活这条规则",
      "steps": [
        "第一步：他做什么",
        "第二步：他做什么",
        "得出结论"
      ],
      "underlying_assumptions": ["FA-01", "FA-03"],
      "evidence": [
        {
          "source": "文章X·第Y段",
          "quote": "原文引用",
          "annotation": "哪个部分对应哪个步骤"
        }
      ],
      "validation_cases": [
        {
          "source": "文章Z·第W段",
          "quote": "原文引用",
          "how_it_fits": "如何印证这条规则"
        }
      ],
      "confidence": "高 | 中 | 低",
      "confidence_reason": "置信度依据"
    }
  ],
  "assumption_coverage": {
    "well_supported": ["FA-01被RP-01和RP-02使用"],
    "orphaned": ["FA-02未被任何推理规则使用，可能是独立信念而非推理前提"]
  },
  "extraction_notes": {
    "total_reasoning_segments_analyzed": 数字,
    "patterns_discarded": "被淘汰的候选模式及原因",
    "index_insufficient": "标注为索引内容不足而跳过的段落"
  }
}
```

---

## 硬性约束

- 推理规则数量：3-6条
- 每条规则至少3个独立证据段落
- 规则命名必须描述性，NEVER使用预设框架名
- validation_cases 必须来自 type="判断型" 的段落，不得复用已作为 evidence 的段落
- assumption_coverage 必须填写，孤立假设必须标注
- 不得重新扫描原始压缩文本
