# Mirror 项目交互问题诊断报告

**诊断时间**: 2026-05-13  
**诊断范围**: 前端交互体验（HomePage, UploadPage, ProgressPage, ResultPage）  
**诊断方法**: 静态代码审查 + 用户体验分析

---

## 执行摘要

**总问题数**: 15 个  
**严重程度分布**:
- 🔴 高优先级: 6 个（影响核心功能或用户体验）
- 🟡 中优先级: 5 个（影响易用性）
- 🟢 低优先级: 4 个（优化建议）

**核心问题**:
1. **缺少停止/取消任务按钮** — 用户无法中断正在运行的任务
2. **缺少编辑/重试功能** — 任务失败后只能删除重建
3. **缺少批量操作** — 无法批量删除或导出任务
4. **缺少搜索/排序** — 任务多了之后难以查找
5. **缺少实时反馈** — 用户不知道后台在做什么

---

## 问题详情

### 🔴 高优先级问题

#### 问题 1: 缺少停止/取消任务按钮
**位置**: `HomePage.jsx` (任务列表) + `ProgressPage.jsx` (进度页)  
**现象**: 任务开始后无法中断，只能等它跑完或失败  
**影响**: 
- 用户误操作后无法撤销
- 长时间任务无法中途停止
- 浪费 API 额度

**期望行为**:
- 任务列表中 `processing` 状态的任务应该有"停止"按钮
- 进度页应该有"取消任务"按钮
- 停止后任务状态变为 `stopped`，可以重新启动

**修复建议**:
```jsx
// HomePage.jsx - 在操作按钮区域添加
{task.status.includes('processing') && (
  <button
    onClick={() => handleStopTask(task.id)}
    className="px-4 py-2 text-sm text-orange-600 hover:bg-orange-50 transition-colors"
  >
    停止任务
  </button>
)}

// ProgressPage.jsx - 在操作按钮区域添加
{polling && taskData.status !== 'completed' && (
  <button
    onClick={handleStopTask}
    className="px-6 py-3 border border-red-500 text-red-600 hover:bg-red-50 transition-colors"
  >
    停止蒸馏
  </button>
)}
```

**后端 API 需求**: `POST /api/distillations/{id}/stop`

---

#### 问题 2: 缺少编辑/重试功能
**位置**: `HomePage.jsx` + `ProgressPage.jsx`  
**现象**: 任务失败后只能删除重建，无法修改参数重试  
**影响**:
- 用户需要重新输入所有内容
- 无法针对失败原因调整参数
- 体验割裂

**期望行为**:
- 失败任务应该有"重试"按钮（使用相同参数）
- 失败任务应该有"编辑后重试"按钮（跳转到编辑页）
- 已完成任务应该有"基于此创建新任务"按钮

**修复建议**:
```jsx
// HomePage.jsx
{(task.status === 'failed' || task.status === 'stopped') && (
  <>
    <button
      onClick={() => handleRetry(task.id)}
      className="px-4 py-2 text-sm bg-orange-600 text-white hover:bg-orange-700 transition-colors"
    >
      重试
    </button>
    <Link to={`/edit/${task.id}`}>
      <button className="px-4 py-2 text-sm border border-kenya-line hover:bg-kenya-dark/5 transition-colors">
        编辑后重试
      </button>
    </Link>
  </>
)}
```

**后端 API 需求**: 
- `POST /api/distillations/{id}/retry`
- `GET /api/distillations/{id}/raw` (获取原始输入用于编辑)

**修复建议**:

// ProgressPage.jsx - 在进度区域添加

#### 问题 4: 缺少批量操作
**位置**: `HomePage.jsx`  
**现象**: 无法批量删除、导出或管理任务  
**影响**:
- 任务多了之后管理困难
- 需要逐个点击删除
- 无法批量导出结果

**期望行为**:
- 任务列表支持多选（checkbox）
- 顶部显示批量操作栏（删除、导出、标记）
- 支持"全选"和"反选"

**修复建议**:
```jsx
// HomePage.jsx - 添加状态
const [selectedTasks, setSelectedTasks] = useState([]);

// 任务卡片添加 checkbox
<input
  type="checkbox"
  checked={selectedTasks.includes(task.id)}
  onChange={(e) => {
    if (e.target.checked) {
      setSelectedTasks([...selectedTasks, task.id]);
    } else {
      setSelectedTasks(selectedTasks.filter(id => id !== task.id));
    }
  }}
  className="w-5 h-5"
/>

// 顶部添加批量操作栏
{selectedTasks.length > 0 && (
  <div className="kenya-card bg-blue-50 border-l-4 border-blue-500 mb-6">
    <div className="flex items-center justify-between">
      <span className="text-sm">已选择 {selectedTasks.length} 个任务</span>
      <div className="flex gap-3">
        <button onClick={handleBatchDelete} className="px-4 py-2 text-sm text-red-600">
          批量删除
        </button>
        <button onClick={handleBatchExport} className="px-4 py-2 text-sm text-blue-600">
          批量导出
        </button>
        <button onClick={() => setSelectedTasks([])} className="px-4 py-2 text-sm">
          取消选择
        </button>
      </div>
    </div>
  </div>
)}
```

#### 问题 5: 缺少搜索和排序功能
**位置**: `HomePage.jsx`  
**现象**: 任务多了之后无法快速查找  
**影响**:
- 用户需要滚动查找
- 无法按时间、状态、名称排序
- 降低效率

**期望行为**:
- 顶部有搜索框（按任务名称搜索）
- 支持排序（创建时间、更新时间、名称）
- 搜索结果高亮显示

**修复建议**:
```jsx
// HomePage.jsx - 添加搜索和排序
const [searchQuery, setSearchQuery] = useState('');
const [sortBy, setSortBy] = useState('updated_at'); // created_at, name

// 搜索框
<div className="mb-6">
  <input
    type="text"
    placeholder="搜索任务名称..."
    value={searchQuery}
    onChange={(e) => setSearchQuery(e.target.value)}
    className="kenya-input w-full max-w-md"
  />
</div>

// 排序按钮
<div className="flex gap-2 mb-6">
  <button onClick={() => setSortBy('updated_at')} className={sortBy === 'updated_at' ? 'active' : ''}>
    最近更新
  </button>
  <button onClick={() => setSortBy('created_at')} className={sortBy === 'created_at' ? 'active' : ''}>
    创建时间
  </button>
  <button onClick={() => setSortBy('name')} className={sortBy === 'name' ? 'active' : ''}>
    名称
  </button>
</div>

// 过滤逻辑
const filteredTasks = tasks
  .filter(task => {
    if (filter !== 'all') { /* 现有筛选逻辑 */ }
    if (searchQuery) {
      return task.name.toLowerCase().includes(searchQuery.toLowerCase());
    }
    return true;
  })
  .sort((a, b) => {
    if (sortBy === 'name') return a.name.localeCompare(b.name);
    if (sortBy === 'created_at') return new Date(b.created_at) - new Date(a.created_at);
    return new Date(b.updated_at) - new Date(a.updated_at);
  });
```

## 技术债务

### 代码层面
1. **重复的导出逻辑**: `ResultPage.jsx` 底部有重复的导出 JSON 按钮（第 752 行和第 627 行）
2. **状态判断逻辑复杂**: `HomePage.jsx` 的 `getStatusText` 和 `getStatusColor` 函数过长，建议抽离成独立模块
3. **缺少错误边界**: 如果 API 返回数据格式不符合预期，页面会崩溃

### 架构层面
1. **缺少全局状态管理**: 多个页面重复调用 `api.getTask(id)`，建议使用 React Context 或 Zustand
2. **缺少请求缓存**: 每次切换页面都重新请求数据，建议使用 React Query
3. **缺少乐观更新**: 删除任务后需要等待 API 响应才更新 UI，体验不流畅

---

## 总结

Mirror 项目的核心功能完整，但**交互体验确实存在明显短板**，主要体现在：

1. **缺少任务控制能力**（停止、重试、编辑）
2. **缺少批量操作和搜索**（任务多了之后难以管理）
3. **缺少错误反馈**（用户不知道为什么失败）
4. **缺少实时反馈**（进度不够精细）

建议**优先修复前 6 个高优先级问题**，这些问题直接影响核心用户体验。其他问题可以根据用户反馈逐步优化。
