# Mirror 项目 UI 重设计方案

**日期**: 2026-05-14  
**问题诊断**: 设计系统缺失导致的结构性问题  
**修改原则**: 遵守 AGENTS.md — 最小化修改，外科手术式调整

---

## 问题诊断总结

当前 UI 的核心问题不是"缺少设计"，而是**缺少设计系统**：
- 没有视觉层级系统（所有元素权重相同）
- 没有空间系统（间距随意、容器缺失）
- 没有按钮优先级系统（主次不分）
- 没有排版系统（标题和正文关系弱）

结果：页面看起来像"组件 demo 拼接页"，不像产品界面。

---

## 7 个核心问题 + 解决方案

### 问题 1：页面没有视觉重心

**现象**：
- 首页：Hero 区太空（py-16），任务列表又太挤（space-y-4）
- 结果页：标题巨大（PageTitle 默认样式），内容区像后台系统
- 用户不知道第一眼该看哪里

**根本原因**：
- 没有定义"主内容区"和"次要区域"的视觉权重
- 所有区域用相同的 padding/margin，没有层级

**解决方案**：
1. **建立视觉层级系统**：
   - Hero 区：减少 padding（py-16 → py-12），增加内容密度
   - 主内容区：增加视觉权重（背景色对比、边框、阴影）
   - 次要区域：降低对比度（浅色背景、小字号）

2. **首页调整**：
   - Hero 区：py-16 → py-12，标题和按钮距离缩小
   - 任务列表：添加"内容容器"概念（白色背景卡片包裹整个列表区）
   - 任务卡片：减少高度（p-6 → p-4），信息更紧凑

3. **结果页调整**：
   - 标题区：py-12 → py-8，标题字号缩小
   - 内容区：添加最大宽度限制（max-w-5xl），居中显示
   - 导出按钮：移到固定位置（右上角或底部操作栏）

**文件改动**：
- `HomePage.jsx`：Hero 区 padding、任务列表容器
- `ResultPage.jsx`：标题区 padding、内容宽度限制
- `PageTitle.jsx`：字号调整（可选）
- `TaskCard.jsx`：padding 和信息密度

### 问题 2：按钮优先级错乱

**现象**：
- "创建新任务"、"查看结果"、"导出"、"删除" 视觉等级完全一致
- 用户无法判断哪个是主操作

**根本原因**：
- 只有 `PrimaryButton`、`SecondaryButton`、`DangerButton` 三种样式
- 但实际使用时没有遵守优先级规则
- 例如：首页两个"创建新任务"按钮都是 `PrimaryButton`（Hero 区 + 列表区）

**解决方案**：
1. **建立按钮优先级系统**（每页只能有 1 个主按钮）：
   - **Primary**（主操作）：深色背景 + 浅色文字 + 加粗 + 阴影
   - **Secondary**（次要操作）：浅色背景 + 深色文字 + 细边框
   - **Tertiary**（第三级操作）：透明背景 + 深色文字 + 无边框（仅 hover 时显示）
   - **Danger**（危险操作）：红色背景 + 白色文字（保持现有样式）

2. **首页按钮调整**：
   - Hero 区"开始使用" → Primary（保持）
   - 列表区"创建新任务" → Secondary（降级）
   - 任务卡片"查看结果/进度" → Secondary（保持）
   - 任务卡片"删除" → Tertiary（降级，只在 hover 时显示）

3. **结果页按钮调整**：
   - 导出按钮 → Tertiary（降级，移到右上角）
   - "返回进度页" → Secondary
   - "返回首页" → Tertiary

**文件改动**：
- 新增 `TertiaryButton.jsx`（透明背景、无边框、hover 时显示边框）
- `HomePage.jsx`：列表区"创建新任务"改为 Secondary
- `TaskCard.jsx`："删除"改为 Tertiary，hover 时显示
- `ResultPage.jsx`：导出按钮改为 Tertiary，移到右上角

### 问题 3：空间系统完全不统一

**现象**：
- Hero 区离顶部太远（py-16）
- 卡片 padding 不一致（p-6 vs p-4）
- Tab 和列表距离奇怪（mt-6）
- 按钮与内容不在同一基线

**根本原因**：
- 没有定义统一的间距系统
- 使用 Tailwind 默认值（gap-2, gap-4, gap-6）但没有规则

**解决方案**：
1. **建立 8px 间距系统**（Tailwind 的 4px 基础 × 2）：
   - **xs**: 8px (gap-2, p-2) — 按钮内部、图标间距
   - **sm**: 16px (gap-4, p-4) — 卡片内部、表单字段
   - **md**: 24px (gap-6, p-6) — 区块间距、section 分隔
   - **lg**: 32px (gap-8, p-8) — 大区块间距
   - **xl**: 48px (gap-12, py-12) — Hero 区、页面顶部

2. **统一规则**：
   - Hero 区：py-12（48px）
   - 主内容区顶部：mt-8（32px）
   - 卡片内部：p-4（16px）
   - 卡片之间：space-y-3（12px，视觉更紧凑）
   - 按钮组：gap-3（12px）
   - 区块标题和内容：mb-6（24px）

**文件改动**：
- `HomePage.jsx`：Hero py-16 → py-12，列表 mt-6 → mt-8
- `TaskCard.jsx`：p-6 → p-4
- `ResultPage.jsx`：Hero py-12 → py-8，内容区 mt-6 → mt-8

### 问题 4：缺少"内容容器"

**现象**：
- 所有东西直接铺在白底上
- 页面没有聚焦感、没有阅读区域、没有密度控制

**根本原因**：
- `PageContainer` 只是一个宽度限制（max-w-7xl + padding）
- 没有"主内容卡片"的概念

**解决方案**：
1. **引入"内容容器"概念**：
   - 任务列表区：用白色背景卡片包裹（标题 + Tab + 列表）
   - 结果页内容区：用白色背景卡片包裹（Tab + 内容 + 导出按钮）

2. **容器样式**：
   ```jsx
   <div className="bg-white border border-kenya-line rounded-lg p-6 shadow-sm">
     {/* 主内容 */}
   </div>
   ```

3. **视觉效果**：
   - 主内容区从背景中"浮起来"
   - 用户视线自然聚焦到白色卡片区域
   - 页面有了明确的"阅读区"和"背景区"

**文件改动**：
- `HomePage.jsx`：任务列表区包裹在容器内
- `ResultPage.jsx`：内容区包裹在容器内（已有 ResultCard，检查是否需要调整）

### 问题 5：卡片像"表单盒子"

**现象**：
- 任务卡片太高（p-6 + 多行信息）
- 信息太少（只有名称、状态、时间）
- 右侧按钮漂浮
- 视觉效率极低（200px 高度只显示 3 条信息）

**根本原因**：
- 卡片设计参考了"表单容器"而不是"列表项"
- 信息排版松散（mb-4, mb-3）

**解决方案**：
1. **压缩卡片高度**：
   - p-6 → p-4（padding 减少）
   - mb-4 → mb-2（标题和状态距离缩小）
   - mb-3 → mb-0（时间信息紧贴状态）

2. **优化信息布局**：
   - 左侧：标题 + 状态（横向排列，节省空间）
   - 右侧：时间 + 按钮（对齐）
   - 进度条：保持独立一行（processing 状态时显示）

3. **视觉效果**：
   - 卡片高度从 ~200px 降到 ~120px（无进度条时）
   - 信息密度提升，用户可以一屏看到更多任务

**文件改动**：
- `TaskCard.jsx`：padding、间距、布局调整

### 问题 6：缺少真正的排版系统

**现象**：
- 所有字都像一个等级
- 标题和正文关系弱
- 信息扫描效率低
- 结果页"表达策略分析"和描述文字没有层级

**根本原因**：
- 只定义了字号（text-lg, text-2xl）
- 没有定义字重（font-weight）、行高（line-height）、颜色对比

**解决方案**：
1. **建立排版层级系统**：
   - **H1**（页面标题）：text-4xl font-bold text-kenya-dark
   - **H2**（区块标题）：text-2xl font-semibold text-kenya-dark
   - **H3**（小节标题）：text-xl font-semibold text-kenya-dark
   - **H4**（卡片标题）：text-lg font-medium text-kenya-dark
   - **Body**（正文）：text-base text-kenya-dark/90
   - **Caption**（辅助文字）：text-sm text-kenya-dark/60

2. **颜色对比规则**：
   - 标题：text-kenya-dark（100% 不透明）
   - 正文：text-kenya-dark/90（90% 不透明）
   - 辅助：text-kenya-dark/60（60% 不透明）

3. **行高规则**：
   - 标题：leading-tight（1.25）
   - 正文：leading-normal（1.5）
   - 长文本：leading-relaxed（1.75）

**文件改动**：
- `ResultPage.jsx`：标题和描述文字添加层级样式
- `TaskCard.jsx`：标题 font-semibold → font-medium
- `PageTitle.jsx`：检查是否需要调整默认样式

### 问题 7：UI 风格不统一

**现象**：
- 同时存在：极简白底、中文工具风、轻后台风、原型图风格、论文排版感
- 没有形成统一语言

**根本原因**：
- 没有明确的设计语言定义
- 组件样式各自独立，没有统一的 design token

**解决方案**：
1. **明确设计语言**：Kenya Hara 极简主义
   - **色彩**：kenya-cream（米白）、kenya-dark（深棕）、kenya-line（浅棕边框）
   - **圆角**：统一使用 rounded-lg（8px）
   - **阴影**：最小化使用，仅用于"浮起"效果（shadow-sm）
   - **边框**：统一使用 border-kenya-line
   - **字体**：系统默认（保持）

2. **统一组件样式**：
   - 所有卡片：bg-white border border-kenya-line rounded-lg
   - 所有按钮：rounded-lg（不用 rounded-full）
   - 所有输入框：border-kenya-line focus:border-kenya-dark

3. **去除不一致元素**：
   - 检查是否有 emoji 图标（应该用 SVG 或文字）
   - 检查是否有不同的圆角值（统一为 rounded-lg）
   - 检查是否有不同的阴影值（统一为 shadow-sm 或无阴影）

**文件改动**：
- 全局检查所有组件的 className
- 统一圆角、边框、阴影样式

## 注意事项

1. **遵守 AGENTS.md 规则**：
   - 只改必须改的文件
   - 不顺手重构无关代码
   - 匹配现有代码风格

2. **分阶段执行**：
   - 每个阶段独立验证
   - 不要一次性改完所有问题

3. **前端构建**：
   - 每次修改后运行 `npm run build`
   - 浏览器硬刷新确认效果

4. **不做移动端适配**：
   - 所有修改只针对桌面端
   - 不添加移动端断点
   - 不调整触摸目标大小
